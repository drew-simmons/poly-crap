# Security Policy

## Supported versions

Security fixes cover the latest released version of `poly-crap`.
Upgrade before you report a flaw that may already have a fix.

## Reporting a vulnerability

Report vulnerabilities through GitHub's private
[security advisory form](https://github.com/drew-simmons/poly-crap/security/advisories/new).

> [!WARNING]
> Do not open a public issue for suspected command injection, unsafe file
> access, installer flaws, an authentication bypass, or credential exposure.

Include the affected version, operating system, steps to reproduce the issue,
expected behavior, and possible impact. Remove tokens, credentials, personal
data, and all other secrets from reports and logs.

You should receive an acknowledgment within seven days. Confirmed issues will
be handled in private until a fix and disclosure plan are ready.
